安装（Windows 优先）

两个独立二进制：hearth（交互式 TUI）与 hearth-agent（无头自动化），可分别安装。

Windows

# 方式一：源码构建（产出 zip + sha256 到 dist\<版本>\）
git clone https://github.com/flairamos/hearth && cd hearth
.\scripts\build.ps1            # 加 -All 构建全平台矩阵

# 方式二：把构建产物放进 PATH
Copy-Item dist\0.4.2\*.exe $env:USERPROFILE\bin\

# 方式三：Scoop（发布后）
scoop bucket add hearth https://github.com/flairamos/hearth
scoop install hearth           # 同时安装 hearth 与 hearth-agent

Windows 启动方式

Release 的 *​_windows_amd64.zip 内含全部所需文件：

方式说明
双击 run-tui.cmd自动打开 Windows Terminal（无 WT 时用 cmd）并启动界面
双击 run-agent.cmd打开终端并显示 hearth-agent 用法示例
终端运行 hearth解压后加入 PATH，直接运行
认准产物：请解压 *​_windows_*.zip 里的 .exe —— linux/macOS 产物没有扩展名，双击会弹「选择打开方式」。
SmartScreen：拦截时点「更多信息 → 仍要运行」，或 PowerShell 执行 Unblock-File .\hearth.exe。
报错不闪退：双击 exe 遇错时窗口会保留（press Enter to close）。最常见原因是 Ollama 未启动 —— 先运行 ollama serve。

Linux / macOS

git clone https://github.com/flairamos/hearth && cd hearth
./scripts/build.sh
sudo cp dist/0.4.2/hearth{,-agent}_linux_amd64 /usr/local/bin/
# 或: go install ./cmd/hearth ./cmd/hearth-agent

启动与后端自动发现

# 准备本地模型（任选一种本地后端）
ollama pull qwen3.5:4b

hearth                          # 交互式 TUI
hearth-agent agent "统计行数" --yolo   # 无头自动化
hearth-agent ask "一句话解释 TCP"      # 单问
hearth-agent models              # 列出后端模型（含能力列）

程序启动时按以下顺序解析后端：

  1. 配置文件中的 ollama_url
  2. 自动探测常见本地端口：Ollama :11434（原生 + /v1）、LM Studio :1234、llama.cpp :8080、vLLM :8000、Jan :1337
  3. 找到后写回配置文件，下次启动秒连

全部失败时 TUI 显示引导卡片（原因 + ollama serve 提示 + 检测命令 + r 重试）。

配置与迁移

平台配置文件数据 / 会话
Windows%AppData%\hearth\config.json%AppData%\hearth\
Linux / macOS~/.config/hearth/config.json~/.local/share/hearth/
旧版迁移：之前用 ollama-tui 的配置与会话会被自动沿用（旧路径回退），无需手动迁移。

环境变量：HEARTH_CONFIG / HEARTH_DATA（旧 OLLAMA_TUI_* 兼容）。

从源码构建

依赖：Go 1.22+（无 CGO，纯静态）。

go build -o hearth ./cmd/hearth
go build -o hearth-agent ./cmd/hearth-agent

# 全平台矩阵（linux/darwin tar.gz；windows 走 build.ps1）
./scripts/build.sh

GitHub Releases 提供各平台 zip / tar.gz 与 SHA256 校验（.github/workflows/release.yml 自动构建）。
