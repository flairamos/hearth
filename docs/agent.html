hearth-agent — 无头自动化

独立二进制（~11MB），零 TUI 依赖：没有终端的服务器、CI 流水线、脚本里都能跑。与 TUI 共享同一套配置、后端自动发现与 agent 内核。

# 让 agent 干活（工作目录 -w，免审批 --yolo）
hearth-agent agent -m qwen3.5:4b -w ./myproject \
  "统计 src 下所有 Go 文件的行数，写一个报告 report.md" --yolo

# OpenAI 兼容后端
hearth-agent agent "检查 test.txt 是否包含 TODO" --api-style openai

# CI / 脚本消费事件流（NDJSON）
hearth-agent agent "…" --json | jq 'select(.event=="done")'

# 单问（无工具）
hearth-agent ask "一句话解释什么是 keep_alive"

# 列出后端模型（含大小/量化/能力）
hearth-agent models

命令与参数

命令参数
agent "task" -m 模型名 · -w 工作目录 · --yolo 免审批 · --perm ask|risky|full · --max-steps 步数预算 · --json NDJSON 事件 · --show-thinking 输出思考流 · -url 后端地址 · -api-style ollama|openai
ask "question"-m · -url · -api-style（流式输出，末行显示吞吐统计）
models-url · -api-style

内置工具（13 个）

类别工具说明

计算calculator纯 Go 表达式求值：+ - * / % ^、sqrt/log/min/max…（无 shell 依赖）

access 权限三档

档位行为
ask变更前询问：写文件 / 执行命令 / 写记忆全部弹审批
risky有风险才询问：只读命令白名单（ls/cat/git status…含 PowerShell 别名）与工作目录内写入自动放行；其余询问
full完全自主：全部自动执行
安全底线：危险命令模式（rm -rf、sudo、curl|sh、git push -f、del /s、format C:、Remove-Item -Recurse 等）在任何档位（含 full / --yolo）都强制人工确认；headless 无人工时自动拒绝并回传给模型自纠。

无人工环境可用 OLLAMA_TUI_AGENT_APPROVE=1（每工具确认一次）或 --yolo 完全放行。

--json 事件流

{"event":"tool_start", "tool":"bash", "args":"{\"command\":\"ls\"}"}
{"event":"tool_result", "tool":"bash", "output":"...", "error":false}
{"event":"content", "text":"## 完成\n..."}
{"event":"done", "steps":4, "tool_calls":3, "prompt_tokens":5172,
 "output_tokens":515, "seconds":10.4, "interrupted":false}

配合 jq 即可把 agent 嵌入任何流水线。退出码：0 成功 / 1 失败 / 2 用法错误。

为本地小模型做的优化

  • 原生 tool_calls 通道优先，模型退化为文本输出时 <tool_call> 协议兜底解析
  • 工具错误原文回传（含可用函数清单），实测模型据此自纠（factorial → 连乘表达式）
  • 步数预算 + 剩余步数提醒；预算用尽自动追加一轮「无工具总结」收尾
  • 上下文卫生：thinking 不回传、陈旧工具结果截断、超限自动裁剪重试、易变注入移到消息尾部保住前缀缓存
  • keep_alive 模型常驻 —— 多步任务壁钟 -22%，单轮吞吐达裸 API 上限的 99.6%
